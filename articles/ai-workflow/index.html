我的 AI 工作流实战

从科研、学习到办公，用 Agent 把效率串成链

过去一年，我逐渐把 AI 从"聊天工具"变成了真正的"执行助手"。

这篇文章不是工具评测，而是三套我已经跑通的工作流：科研、学习、办公。核心思路只有一个——让 Agent 做重复性执行，我专注于判断和创造。

一、先厘清两个概念

1. Agent：不只是会聊天的 AI

传统聊天机器人是"你问一句，它答一句"。Agent（智能体）则能自己规划、调用工具、反复尝试，直到把任务做完。它的典型循环是：接收目标 → 思考规划 → 调用工具 → 观察结果 → 交付结果；未完成则继续循环。

一句话总结：Agent = LLM 大脑 + 记忆 + 工具 + 自主循环。

2. 工作流：把工具串成链

工作流（Workflow）是把一系列任务按固定或半固定顺序连接起来的流程。当 Agent 嵌入工作流，原本需要手动操作多个软件的环节，可以自动流转。工作流的本质不是"用得越多越好"，而是让每个工具在自己擅长的环节发挥作用，减少切换和重复劳动。

核心理念：让 Agent 做执行，你做决策。

二、科研工作流

核心痛点：文献管理混乱、笔记分散、引用格式繁琐、写文章时反复切换窗口。

我的工具栈：

工具 作用
Zotero文献管理与 PDF 阅读
llm-for-zotero在 Zotero 里直接调用 AI 总结论文
Obsidian个人知识库，双向链接
obsidian-vault-mcp让 Agent 通过 MCP 读写 Obsidian 笔记
drawio / excalidraw画概念图、流程图
nano banana科研数据可视化

推荐安装：

1. llm-for-zotero（github.com/yilewang/llm-for-zotero）：在 Zotero 中直接调用 AI，快速提取摘要、方法、实验结果。

2. obsidian-vault-mcp（github.com/luffysolution-svg/obsidian-vault-mcp）：让 Agent 真正操作本地知识库，实现读写笔记、关联知识。

关键收益：文献不再沉睡，笔记自动生长，输出更连贯。

三、学习工作流

核心思路：学习的关键不是"存了多少资料"，而是知识有没有经过自己的处理。流程是：输入 → 处理 → 输出 → 复习，形成闭环。

我的工具栈：

工具 作用
Obsidian知识库主阵地
日历 / 看板 / 模板 / Dataview让笔记结构化、可查询
karpathy-llm-wiki-vault基于 Karpathy 教程的 LLM 知识库
SyncthingPC 与平板间零延迟同步
Ink / Mobile Ink Annotation平板手写批注，保留纸笔体验

推荐资源：

• karpathy-llm-wiki-vault（github.com/jason-effi-lab/karpathy-llm-wiki-vault）：把 Karpathy 的 LLM 课程整理成可学习的 Obsidian 知识库。

• Syncthing：点对点同步，不依赖云盘，适合多设备同步 Obsidian 库。

• Ink / Mobile Ink Annotation：平板端手写批注，适合公式推导和草图记录。

关键收益：笔记即学习过程，跨设备无缝，复习有抓手。

四、办公工作流

核心痛点：信息散落在聊天、文档、审批、多维表格里，手动复制粘贴、发通知、整理会议纪要的重复劳动多。

我的工具栈：

工具 作用
飞书 CLI命令行操作飞书，批量处理文档、表格、消息
Workbuddy飞书生态内的 AI 助手，替代传统飞书机器人
Agent编排任务、调用飞书 API、读写文档与表格

典型场景：

  • 每日站会摘要：Agent 读取日程和待办，自动生成摘要，通过飞书 CLI 发送到群聊；
  • 文档管理：Agent 定期扫描云文档，自动归档过期会议纪要和临时文件；
  • 多维表格自动化：任务状态变更后，Agent 自动更新多维表格并生成周报；
  • 替代传统飞书机器人：飞书原生的机器人能力有限、配置复杂；Workbuddy + Agent 可根据自然语言指令灵活执行，实现文档、表格、消息、审批的集中管理。

关键收益：协作信息自动流转，自然语言即可操作，可替代传统机器人。

五、总结

三套工作流的核心不是用了多少工具，而是让信息在正确的环节自动流动。

场景 核心链条
科研Zotero → Obsidian → Agent → 综述 / 论文
学习输入 → Obsidian 处理 → 输出 → Syncthing 同步 → 复习
办公飞书 CLI + Agent / Workbuddy → 文档 / 表格 / 消息 / 审批

如果你刚开始搭建自己的工作流，建议先选一个最痛的场景跑通，再逐步扩展。不要追求一步到位，先让工具链转起来，再迭代优化。

工具是手段，效率是目的。Agent 负责执行，你负责思考。
