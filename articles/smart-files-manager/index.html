Smart Files Manager：会商量、能反悔的 AI 文件整理助手

文 / 龙川武生原稿记录 2026-08-17约 6 分钟

你的「下载」文件夹是不是已经堆了三年？微信接收的文件散落在十几个角落，桌面图标密密麻麻，想整理一次，又怕删错重要资料、怕不小心动了隐私文件、怕整理到一半后悔莫及……

今天介绍我自己写的一个开源小工具 / Skill：Smart Files Manager（智能文件整理助手）。它不会替你莽撞地删除文件，而是先和你"商量边界"，再动手；所有落地动作默认只做复制、并且能一键回滚。

一、它到底解决什么

我们每个人都有"文件焦虑"：

  • 乱：下载、微信、桌面、各种临时目录，文件像野草一样疯长；
  • 怕：想整理，又怕误删、怕覆盖、怕动了密码和密钥；
  • 烦：大文件、缓存、媒体塞满硬盘，手动分类费时费力；
  • 悔：整理完才发现分类不对，却已经改不动了。

市面上的整理工具大多"一键梭哈"——直接移动、删除、重命名，出错就难以挽回。Smart Files Manager 的设计哲学恰恰相反：先审查、再协商、后落地，且全程可反悔。

二、它是什么

一句话：一个个性化 + 交互式 + 人工审核闭环的通用文件管理自动化工具。

  • 它不限于微信文件——你可以一次性传入任意多个待整理目录，统一聚合扫描、出方案、做落地；
  • 它既是可独立运行的命令行工具（纯 Python），也是 opencode / Claude Agent 的 Skill 包——复制仓库目录加入技能路径即可；
  • 它零第三方依赖，仅用 Python 标准库，Windows 下开箱即用（自动处理 260 字符长路径）。

三、核心特性：为什么敢放心交给它

  • 多目录输入 — 一次传入多个待整理目录，统一聚合扫描 / 方案 / 落地；
  • 隐私保护 — .env、*.pem/.key/.p12、密码 / 密钥 / 凭据目录、.ssh、Thumbs.db 等命中即跳过，整棵子树连清单都不枚举；
  • 性能敏感保护 — 超过 200MB、缓存目录、node_modules、Git 内部、二进制 / 媒体 / 压缩包：只报告，不读取、不复制、不移动；
  • 边界与权限协商 — analyze.py 产出只读审查报告，动手前用 4 个问题与你确认；
  • 人工审核闭环 — recommend.py 生成方案 → 你逐条批准 → apply.py 才落地；
  • 智能去重 — 目标已存在：内容一致就跳过，不一致自动加 _1 序号保留全部版本；
  • 可回滚 — 每次落地写操作日志，--undo 一键反向；
  • 持续学习 — 从已有仓库学分类 / 命名；反馈写入 habits.md，下次自动遵守；
  • 零第三方依赖 — 仅 Python 标准库，Windows 下开箱即用。

四、怎么装

方式一：当命令行工具用

# 1. 检查 Python 版本（需 3.8+） python --version # 2. 克隆仓库 git clone https://github.com/Longlong-hub/smart-files-manager.git cd smart-files-manager

方式二：当 AI Agent 的 Skill 用

把仓库目录复制到你 Agent 的技能路径下即可（例如 opencode / Claude Agent 的 skills 目录）。具体路径见仓库 README 的「Skill 路径」说明。

五、四步上手（Quick Start）

第 1 步：边界与权限审查（只读，不碰任何文件）

python scripts/analyze.py "D:\杂乱文件A" "D:\杂乱文件B"

你会看到一份审查报告：整理候选 / 隐私跳过 / 性能跳过 / 待确认问题清单。先逐条确认规则，再进入下一步。

第 2 步：扫描并生成方案

# 扫描（候选清单 + 画像推断） python scripts/scan.py "D:\杂乱文件A" "D:\杂乱文件B" --out state/scan_report.md # 生成分类+命名方案（写入 state/pending_plan.md） python scripts/recommend.py "D:\杂乱文件A" "D:\杂乱文件B" # 预览方案 python scripts/review.py state/pending_plan.md

第 3 步：人工审核后落地

# 默认复制，目标根目录 D:\文件整理（也可用 --dst 指定） python scripts/apply.py state/pending_plan.md --dst "D:\文件整理" # 出错了？一键回滚 python scripts/apply.py --undo "state\logs\apply_20260807_120501.json"

⚠️ 红线：任何写 / 删 / 移动操作，必须先产出方案并经过你批准。默认只做复制，移动必须你明确要求。

六、一处配置，改边界不改代码

所有边界都在 config/rules.json 一处维护，改配置不用动代码：

字段 作用 默认示例
文档后缀哪些扩展名算"待整理候选".doc .docx .pdf .xlsx .md .png …
隐私跳过.文件名命中即跳过的文件名（* 通配）*password*、*.pem、.env
隐私跳过.目录命中即跳过的目录/.ssh/、AppData、/凭据/
性能敏感.最小跳过MB超过该大小的文件跳过200
性能敏感.目录缓存 / 依赖 / 临时目录node_modules、.git、cache、temp
性能敏感.后缀二进制 / 媒体 / 归档扩展名.exe .dll .mp4 .zip .sqlite …
跳过不整理无条件跳过.idea、.vscode、*.bak
整理后目的根落地目标根（apply 默认 --dst）E:\文件整理

七、动手前必问的 4 件事

在跑扫描 / 落地之前，analyze.py 会引导你和它确认这 4 个问题：

  • 隐私跳过规则是否符合预期？（可增删 config/rules.json 条目）
  • 动作是复制（保留原件）还是移动？
  • 同名文件冲突处理：跳过 / 自动加序号 / 询问？
  • 是否允许读取文件内容做智能分类 / 去重？（隐私与性能文件除外）

边界讨论完成前，工具不会进入扫描 / 落地阶段。

八、你可能关心的问题（FAQ）

Q：能整理微信 / QQ 的接收文件夹吗？
可以。微信 / QQ / 任意目录都只是"待整理目录"，直接传给 analyze.py / scan.py 即可。

Q：会读到我的隐私内容吗？
默认不会。隐私文件匹配后就被整棵跳过，连清单都不枚举；analyze.py 报告会明确列出哪些目录被整棵跳过。

Q：支持哪些平台？
Windows / macOS / Linux 均可。Windows 下自动用 \\?\ 长路径前缀，超过 260 字符的路径不受影响。

写在最后

文件整理从来不是"删得多"就好，而是"整理得安心"才重要。Smart Files Manager 把这件事交还给你：你来定边界，它来出方案，你有最终否决权，而且随时能反悔。
