诗云 · Literature Vault：给 Obsidian 装上文学可视化引擎

文 / 龙川武生原稿记录 2026-08-17约 8 分钟

提笔时千言万语，落笔后无人问津——这大概是每个写作者都隐秘的遗憾。

我们写诗、写散文、写随感，把某一刻的欢喜与怅惘都交付给文字。可这些文字，往往写完就被收进 Obsidian 的某个角落：标签越积越乱，检索越来越难，时间一久，连自己都忘了曾写下过什么。它们不是消失了，只是「沉」了下去——写时有多真切，沉时就有多可惜。

我一直想给这些文字一个更好的去处：不是冷冰冰的仓库，而是一座能被看见、被品味、被持续翻阅的个人文学馆。于是有了今天这个开源项目：诗云 · Literature Vault。它提供一套完整的文学知识库规范，并配一个零依赖的本地可视化服务，让「一个人 + AI」也能把 Obsidian 变成可归档、可检索、可赏析的文学仓库。

一、它到底解决什么

文学创作者常见的几个痛点：

  • 散：诗作、文选、摘录、专辑散落在不同目录，没有统一归档；
  • 乱：标签、分类、命名随心所欲，时间久了连自己都找不到；
  • 沉：写完就忘，没有总目、年选集和赏析体系；
  • 孤：Obsidian 里只能看纯文本，缺少对诗的可视化品味与赏析互动。

Literature Vault 把「仓库规范 + 可视化服务」打包给你：先按约定把文字整理好，再通过诗云服务把它们「品」成词云、「赏」成篇章。

二、它是什么

一句话：一套可直接挂在 Obsidian 文学库上的「规范 + 可视化」方案。

  • 知识库规范：raw 写作区 → wiki 归档区的双维度归档体系；frontmatter 规范、8 主题分类、5 大体裁识别、随吟/专辑拆分、总目与日志管理，配套 Agent Skill（ingest / query / lint）。
  • 诗云可视化：纯 Node.js 零依赖本地服务（端口 8899）。「品」看诗字形词云；「赏」看逐篇赏析；可选一键调用大模型即时生评；支持 Obsidian Local REST API 实时数据源切换。

三、核心特性

知识库侧

  • 双维度归档：按「语言 → 主题」与「年份 → 语言 → 主题」自动组织；
  • Frontmatter 规范：诗 / 文选 / 摘录 / 专辑 / 赏析五种文档类型统一定义（含干支纪年时间戳）；
  • 体裁识别：近体诗 / 词 / 现代诗 / 随吟 / 英文诗 五类，AI 自动判定；
  • 随吟拆分：一行一首的随吟写作区，归档时自动按首拆分为独立诗篇；
  • 专辑拆分：多语言混合专辑按日期拆分为独立诗歌入档；
  • 文学检索与健康巡检：/query 双链式检索、/lint 死链/孤岛/格式体检；
  • 赏析体系：每篇赏析对应一首已归档作品，含 rating 与 best_line。

诗云侧（零依赖，纯 Node 标准库）

  • 品：实时读取归档诗集，基于整理自 chinese-poetry/chinese-poetry 开源诗词数据集的分词词库生成诗字形词云；
  • 赏：优先展示有赏析的作品，按体裁选取段落；无赏析可一键 AI 生评；
  • 双数据源：默认直读本地文件；接入 Obsidian Local REST API 后自动切换；
  • 配置热更新：config.json 管理数据源与 LLM 参数，网页端可改。

四、快速开始

环境要求

  • Node.js ≥ 18（内置 fetch）
  • 一个按本仓库规范组织的 Obsidian 文学知识库（见 docs/知识库建立与管理.md）
即使完全不懂 Node、不写配置，也能让 agent 帮你跑起来。下面先给最省事的 agent 路线，再附手动步骤备用。

最省事：用 Agent 一站式配置项目并搭建诗云（推荐）

目录、配置、启动这些事，其实都可以交给一个 AI Agent 替你做完，你完全不必手动照着下面的步骤来。把本仓库（连同 docs/ 规范文档）交给任意支持读写文件的智能体（Claude Code、Opencode，或你正在用的 WorkBuddy 这类），对它说「按本仓库规范帮我初始化文学库并启动诗云」，它就会参照 docs/ 自动完成：

  • 初始化目录结构：按规范生成 raw/（诗集 / 文选 / 专辑 / 收藏）、wiki/（归档 / 赏析 / 年选集 + index.md / log.md）、诗云/ 整套骨架；
  • 配置 config.json：按你的笔名、是否接 Obsidian、是否接大模型，写好 source / author / llm 三项；
  • 搭建并启动诗云：放好 server.js 与 index.html，运行 node server.js（Windows 也可双击 start.bat），打开 http://localhost:8899 即见「品」「赏」；
  • 之后持续维护：新作归档用 /ingest <文件>、体检用 /lint、检索用 /query——三套 Agent Skill 让「写作 → 归档 → 赏析 → 检索」全程不用手敲规范。

一句话：你把文字写进 raw/，目录、配置、启动、归档都交给 agent，剩下的只是打开网页欣赏。

1. 目录约定

你的文学库/ ├── raw/ # 写作区 │ ├── 诗集/ │ ├── 文选/ │ ├── 专辑/ │ └── 收藏/ ├── wiki/ # 输出层 │ ├── 归档/ │ ├── 赏析/ │ ├── 年选集/ │ ├── index.md │ └── log.md └── 诗云/ # 本可视化系统

2. 启动诗云

Windows：双击 诗云/start.bat，或运行 node server.js。

macOS / Linux：

cd 诗云 node server.js

浏览器打开 http://localhost:8899。

提示：server.js 默认从 ../wiki/归档/诗集 与 ../wiki/赏析 读取数据，请保证诗云目录位于文学库根目录下。

3. 配置（可选）

config.json（不入 git）：

{ "source": "auto", "author": "你的笔名", "llm": { "base": "https://api.deepseek.com", "key": "sk-xxx", "model": "deepseek-v4-pro" } }

4. 接入 Obsidian 实时数据源

  • 安装社区插件 Obsidian Local REST API；
  • 启用 Enable Insecure Server，记住端口（默认 27123）；
  • 设置页获取 API Key；
  • 网页右上角数据源切到 Obsidian，或把 config.json 的 source 设为 "obsidian"。

5. 接入大模型

网页「一键生评」或前端配置项填入 base / key / model。兼容 OpenAI Chat Completions 协议（DeepSeek、通义、Moonshot 等）。

6. 用 Agent 一站式配置项目并搭建诗云（推荐）

前面 1–5 步的目录、配置、启动，其实都可以交给一个 AI Agent 替你做完。把本仓库（连同 docs/ 规范文档）交给任意支持读写文件的智能体（Claude Code、Opencode，或你正在用的 WorkBuddy 这类），对它说「按本仓库规范帮我初始化文学库并启动诗云」，它就会参照 docs/ 自动完成：

  • 初始化目录结构：按规范生成 raw/（诗集 / 文选 / 专辑 / 收藏）、wiki/（归档 / 赏析 / 年选集 + index.md / log.md）、诗云/ 整套骨架；
  • 配置 config.json：按你的笔名、是否接 Obsidian、是否接大模型，写好 source / author / llm 三项；
  • 搭建并启动诗云：放好 server.js 与 index.html，运行 node server.js（Windows 也可双击 start.bat），打开 http://localhost:8899 即见「品」「赏」；

六、技术细节（可跳过）

放心，它没你想的那么重。诗云是一个零依赖的轻量服务：没有数据库，没有后端框架，整个系统就是一份 server.js。它只对外暴露几个极简接口——取状态、取诗文、取赏析、热更新配置、调用大模型生评——仅此而已。你不必懂接口，双击 start.bat、打开网页就能用。

七、你可能关心的问题（FAQ）

Q：必须搭配 Obsidian 吗？
不一定。诗云默认从本地文件读取，只要目录结构符合规范即可；Obsidian 只是推荐的写作环境。

Q：没有大模型 API 能用吗？
完全可以。「品」和「赏」不依赖 LLM；只有「AI 一键生评」需要配置接口。

Q：支持 Windows 吗？
支持。Windows 下提供 start.bat，双击即可启动。

写在最后

有人说，写诗是和自己说话；我说，把诗安放好，是让未来的自己还能听见当年的声音。

一座个人文学库的意义，从来不在「存了多少字」，而在「这些字有没有被认真地看见过」。Literature Vault 做的，正是这样一件小事：先用一套温柔而清晰的规范，把散落的文字收拢归档；再借「诗云」之手，把它们化作词云、化作篇章，让你随时能回头，与某一年的自己重逢。

如果你也写过不少字、藏过不少心绪，不妨试试把它交给诗云。一个人，加上一点点 AI，也能经营好一座属于自己的文学馆。
